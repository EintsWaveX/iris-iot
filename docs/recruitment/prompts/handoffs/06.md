## Contracts
- API actions (`api/recruitment/[aksi].ts`): `results`, `propose`, `lock`, `unlock`, `envelopes`, `envelope-open`, `qr-events`, `qr-token`, `attend`, `attend-manual`, `attendance`, `slots`, `slot-pick`, `slot-change`, `slot-decide`, `slot-set` (ops `create`, `edit`, `delete`, `move`, `window`), `slot-autofill`; `review` takes a score and a verdict per file. Pure rules: `src/lib/recruitment/{slots,standing,cutting,reveal,qr,reveal-clock}.ts`; handlers `api/_lib/recruitment-{cutting,attendance,slots}.ts`.
- Siaran topics: `reccutting`, `recplotting`, `reccandidates`.
- A candidate's stage and status are worked out when read from the locked results (`standing.ts`); nothing is written at lock time. A sealed envelope carries no result, and before `reveal_at` it looks like no envelope at all.
- QR tokens: HMAC of event and the 20 s period, key `REC_QR_SECRET`, or one derived from `SESSION_SECRET` when it is not set. A scan counts only for a candidate who reached the event's stage and, on a test evening, holds a slot for that day.
- **Which events take a QR (`eventHadir` in `lib/recruitment/gates.ts`):** public events of kind meeting, test, makeup, interview, work, presentation or teaching, or any public event given the `qr` gate; internal events, registration, announcements, picks, reviews, plenos and cuttings do not. The API (`bisaDipindai`) and Ringkasan use the same function.
- Keyframes `rec-s2-*`, CSS classes `r2*`, S3 uses `rec-s3-*` and `r3*`. `Roll` is `components/recruitment/Roll.tsx`.
- RecNav: add tabs by appending to `links` in `RecNav.tsx` and a `PanelTab` key in `lib/recruitment/panel-tab.ts`.
- **Rooms and slots (for 11, agreed with 08c):** a `rec_slot` of stage `tes_tulis` is one exam room on one evening (`room`, `starts_at`, `ends_at`, `capacity`, `event_id`). Key room state by `slot_id`. A seat is the candidate with a `rec_slot_assignment` row on that slot (one row per candidate per stage, UNIQUE on candidate and stage); read the seat list live from the assignments. Key anything stored per seat by `candidate_id` plus the slot the part was started in (the W1 `room` ruling), never by the assignment row id, since an assignment row changes `slot_id` when a seat moves. A Susulan evening is more `rec_slot` rows with `event_id` of the makeup event (`slot-set create` takes an explicit `eventId`). Moving a seat to another room is the Plotting tab's `slot-set { op: "move", candidateId, slotId }` (Panitia with the plotting right, over capacity allowed, via `panitia`, audit line, topic `recplotting`); the seat drawer should call that action and not write assignments itself. EXAM-ENGINE 10.1's `rec_exam_seat.room_id` is either updated in the same transaction by a small hook in the `move` handler (11 messages 06 or W1 first) or derived from the assignment at read time; not decided here.
- Rig scripts: after the oprec accounts (0050) a candidate carries the cookie `iris_oprec` (HMAC domain `oprec\n` + body, `v` = `rec_account.versi`). `rig/rec_lib.mjs` has `cookieFor(role, nim)`, `ensureAccount` and `oprecValue`; `rec_s2_flows.mjs` uses them. The older S1 scripts (`rec_leak.mjs`, `rec_s1_flows.mjs` and others) still use `cookieValue` for candidates; W1 (iris-aso-26) moves them to `cookieFor` when running the leak audit for the accounts ship.
