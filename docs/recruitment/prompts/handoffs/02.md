## Contracts
Everything 03 needs is typed in **`apps/web/src/lib/recruitment/types.ts`** (read it, it is commented). Summary:

**Vocabulary (matches the PRD)**
- Stages (`StageKey`): `berkas, first_meet, tes_tulis, wawancara, tubes, mengajar, penerimaan`.
- Event kinds: `registration, review, announcement, meeting, pleno, test, makeup, cutting, interview, work, presentation, teaching, acceptance`.
- Gates: `daftar, review, qr, exam, cutting, reveal, rubric, topics, checkin, submission, accept`.
- Candidate status: `applied, revision, approved, withdrawn, out, accepted`.
- Document kinds: `cv, letter, vision, biodata, other` (the three required: cv, letter, vision).
- Committee divisions: `ketua, wakil, acara, akademik, logistik, admin, pdd`.
- Phase: `before, open, review, cutting, announced`. Audience: `all, own, offered`.

**Event row (`RecEvent`)**: `id, kind, title, startsOn, endsOn` (WIB dates, inclusive), `dayStart, dayEnd` (`HH:MM` or null), `place, internal, audience, gates[], stage, color, sort`.

**Endpoints** (errors are `{ ok:false, kode }` with a real HTTP status; codes are `RecError` in types.ts; field errors add `field`)

| Action | Who | Request | Response |
|---|---|---|---|
| GET `banner` | anyone | none | `BannerResponse`: `kind` is `none, visitor, praktikan, candidate, cut, panitia, asisten` |
| GET `edition` | anyone | none | `{ edition, viewer, rights, seat }` (rights only for the Panitia and hakPenuh) |
| GET `calendar` | signed in | none | `{ edition, events (already filtered), now }` |
| GET `me` | Praktikan | none | `{ edition, candidate, documents (no ids), envelopes, daftarOpen }` |
| POST `ticket` | Praktikan | `{ kind, ukuran, sha256, halaman? }` | `{ sama:true }` or `{ sama:false, url, tiket }` |
| POST `apply` | Praktikan | `{ biodata, docs:[{kind,tiket}x3], consent:true }` | `{ candidate }` |
| POST `document` | Praktikan | `{ kind, tiket }` | `{ document, status }` |
| POST `withdraw` | Praktikan | none | `{ status:"withdrawn" }` |
| GET `berkas?id=[&unduh=1]` | owner or documents right | none | 302 to a 10 minute relay link |
| GET `candidates?stage=&status=&q=` | Panitia | none | `{ candidates: CandidateRow[] }` (no contact details) |
| GET `candidate?id=` | Panitia | none | `{ candidate, biodata, documents }`; the last two are null without the documents right |
| GET `committee` | Panitia, hakPenuh | none | `{ seats }` |
| POST `review` | approve right | `{ id, decision:"approve"\|"revision", note? }` | `{ status }` |
| POST `event-save` | calendar right | `{ id?, kind, title, startsOn, endsOn, dayStart?, dayEnd?, place?, internal?, audience?, gates?, stage?, color?, confirm? }` | `{ event, logged }` |
| POST `event-move` | calendar right | `{ id, startsOn, endsOn, confirm? }` | `{ event, logged }` |
| POST `event-delete` | calendar right | `{ id, confirm? }` | `{ event:null, logged }` |
| POST `seat` | board right (Ketua row: seatKetua) | `{ nim, division, isKoor?, title? }` | `{ seats }` |
| POST `unseat` | same | `{ nim }` | `{ seats }` |

**Upload flow for 03:** `ticket` (once per file) then PUT the PDF to the returned `url` (no auth header, a plain `PUT` of the bytes) then hand the `tiket` to `apply` (new candidate, all three) or `document` (re-upload). A new applicant has no candidate row yet, so `apply` takes the three tickets itself.

**Confirm rule:** `event-save`, `event-move` and `event-delete` answer **409 `perlu_konfirmasi`** with `event` (an `EventLite`) when the event's stage has started; show a Confirm and send the same request again with `confirm:true`. The response then has `logged:true`.

**Rights** (`RecRights`): `calendar, board, seatKetua, candidates, documents, approve, bank, plotting, plotPengawas, cuttingPropose, cuttingLock, attendance, kitLoans, accept`. Per PRD 4, `wakil` holds only `candidates`. A Koordinator star changes nothing.

**Siaran topics** (letters only): `recedition` (edition and committee seats), `reccalendar`, `reccandidates`. Subscribe with `useSiaran`-style code like the other pages. Message carries names only; refetch `banner`, `calendar`, `me`, `candidates`.

**R2:** key `recruitment/<edition>/<nim>/<kind>/<sha256>.pdf`; PDF only, 5 MB; magic bytes checked by the relay on PUT and again by IRIS on confirm.

**Env:** `SESSION_SECRET` (signs the confirm tickets) and `KONSOL_RELAY_URL` + `KONSOL_RELAY_SECRET` (the relay). Nothing new.

## Rulings I made (the PRD and ARCHITECTURE left these open or conflicted)
1. **Topic names have no hyphen** (`recedition`, `reccalendar`, `reccandidates`): the relay accepts only `/^[a-z]{2,16}$/`. ARCHITECTURE section 5 lists `rec-*`; use these. `rec-room:<id>` is a relay room, not a topic, and is unchanged. Later topics (`reccutting`, `recplotting`, `recbank`) follow the same shape.
2. **`rec_event` gained `stage` and `audience`, and `gates` is an array.** The PRD needs them: a Cutting must say whose stage it is, "own slot only" and "if offered" are not the same as internal, and Presentasi Tubes gates two things. Pengerjaan Tubes gates `checkin` and `qr`.
3. **Penerimaan is not seeded.** The date is TBD and a made-up one would show on candidates' calendars. The Ketua adds it (kind `acceptance`, gate `accept`).
4. **Susulan Wawancara and Susulan Mengajar carry the `rubric` gate** (the PRD left it blank), otherwise their rubric sheets would never open. Presentasi Tubes has no daily window or place (the PRD gives none).
5. **Two readings of a gate:** `gateOpen` is by date (Daftar, Berkas review); `gateLive` also honours the event's daily window (First Meet's QR). The exam engine (08) picks the one it needs; day-wide is the safer default for a test that may overrun 21.00.
6. **Open and Extend count as one registration** for `gateClosesAt` (the Daftar countdown runs to 3 Nov 00.00 WIB). The visitor banner shows the dates of the registration event running now, else the next one.
7. **`rec_committee.asisten_nim`** (not `asisten_id`): `asisten`'s key is the NIM. Partial unique indexes keep one Ketua and one Koordinator per division. Seating a second Koordinator moves the star; Ketua and Wakil carry no star.
8. **Wakil = the PRD's "Other Panitia"** (candidate list only). Shinta's real role is still TBD.
9. **Contact details are Berkas:** the list never carries phone, LINE or address; `candidate` returns biodata and documents only with the documents right (Ketua and Admin).
10. **Re-upload window:** a candidate may upload while Daftar is open, or at any time while their status is `revision` (Admin asked for it, possibly after registration closed). Any upload of an approved or revision candidate puts them back to `applied`. `approve` needs all three documents.
11. **Withdrawn is final:** applying again answers `sudah_daftar`.
12. **Files:** content addressed by SHA-256 (as TP does) instead of a uuid, so a retry lands on the same object. Replaced files stay in R2 until the edition prefix is purged.
13. **Added columns:** `rec_candidate.consent_at, review_note, reviewed_by, reviewed_at`; `rec_document.sha256`; `rec_event_log.edition_id` (and no foreign key on `event_id`, so the log outlives a deleted event).
14. **Existence oracle:** another candidate's document id answers 404 (same as a missing one); a Panitia member without the right gets 403.
15. **Mode TOT dummies** are refused on `me`, `ticket`, `apply`, `document` and `withdraw` (the same `tolakPraktikanTot` as the other Praktikan routes).
